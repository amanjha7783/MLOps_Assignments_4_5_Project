# MLOps Lab Assignments 4–5: MLflow + DVC

This reproducible teaching project uses a **synthetic house-price regression dataset** (`data/dataset.csv`). It is not a real property dataset. The data contains 500 rows, five numeric input features, and target `price_lakh`.

## Environment
Use Python 3.10+ in a virtual environment. Install dependencies with `python -m pip install -r requirements.txt`. Check `mlflow --version` and `dvc --version`.

## Run baseline model comparison
```bash
python src/evaluate.py
python src/train.py
mlflow ui
```
Open `http://127.0.0.1:5000` for the local MLflow UI. `src/train.py` trains three variants, logs metrics, a model signature and input example, and artifacts. `mlflow.sklearn.autolog()` is enabled; inspect each run to verify the actual autologged fields in your installed version.

## Register three versions
The script logs the models and prints run IDs. In an MLflow installation with a model registry enabled, register the three logged model artifacts under one name (e.g. `HousePriceModel`) using the UI or the MLflow client. Verify three distinct versions and record each source run ID. Registry availability depends on MLflow version and tracking-store configuration; do not claim versions exist until verified in the UI.

## Lifecycle policy
Acceptance rule: lowest held-out RMSE among candidates, only if evaluation data is representative and data-quality, latency, fairness, and stability checks pass. Assign `candidate` to the chosen version first; after validation assign the `production` alias if supported. Tag a superseded version `retired` or use the Archived stage where available. Record the decision in the report. A high score alone is not sufficient.

## DVC workflow
Initialize Git first, then run:
```bash
git init
dvc init
git add .dvc .dvcignore .gitignore
git commit -m "Initialize DVC"
dvc add data/dataset.csv
git add data/dataset.csv.dvc .gitignore
git commit -m "Track baseline dataset with DVC"
mkdir ../dvc-storage
dvc remote add -d localremote ../dvc-storage
git add .dvc/config
git commit -m "Configure local DVC remote"
dvc push
```
Make a controlled change to `data/dataset.csv`, run `dvc add data/dataset.csv`, commit the updated `.dvc` metadata, then `dvc push`. To restore an older dataset, use `git log --oneline -- data/dataset.csv.dvc`, check out the matching metadata in a temporary branch/worktree, and run `dvc pull` (or `dvc checkout` if the content is present in cache). Verify row count and SHA-256. Return to the intended latest commit afterwards. A local remote is only for a single-machine exercise, not cloud backup.

## Git + DVC + MLflow linkage
The training script attaches `git_commit` and `dataset_sha256` tags to MLflow runs. Commit code and DVC metadata in Git; keep the dataset object in DVC storage; use MLflow to track run parameters, metrics, artifacts, signatures, and model versions.
